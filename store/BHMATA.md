# Από το κινητό στο Play — κάθε βήμα

Χωρίς υπολογιστή. Όλα από τον browser του κινητού.

Δύο πράγματα είναι **όντως** δύσκολα από κινητό, και δεν θα προσποιηθώ ότι
δεν είναι:

1. **Το πρώτο ανέβασμα του `.aab` στο Play Console.** Το Play δεν έχει mobile
   έκδοση γι' αυτό. Θέλει «Desktop site» στον Chrome, ζουμ, και υπομονή. Είναι
   μία φορά. Μετά όλα τα updates γίνονται με ένα κουμπί.
2. **Το να βγάλεις κείμενο από ένα κατεβασμένο αρχείο `.json`.** Το Android δεν
   ανοίγει `.json` από μόνο του. Θα χρειαστείς έναν text editor από το Play —
   οποιονδήποτε, τζάμπα, μία φορά. Το χρειάζεσαι για δύο (το πολύ τρία)
   αρχεία σε όλη τη διαδικασία.

Όλα τα υπόλοιπα είναι πατήματα σε κουμπιά.

> **Χρησιμοποίησε τον browser, όχι την εφαρμογή GitHub.** Η εφαρμογή δεν έχει
> ούτε Settings → Secrets ούτε «Run workflow». Αν κάπου δεν βλέπεις ένα κουμπί
> που αναφέρω, μενού Chrome (⋮) → **Desktop site**.

**Χρόνος:** περίπου **δύο ώρες** πραγματικής δουλειάς, σπαρμένες σε
**τρεις εβδομάδες** — γιατί στη μέση υπάρχει μια υποχρεωτική δοκιμή 14 ημερών
που δεν επιταχύνεται με τίποτα.

**Κόστος:** 25 δολάρια, μία φορά, στη Google.

---

## Η σειρά, σε μία εικόνα

```
Α. GitHub: token, config, κλειδί            ~20 λεπτά
Β. Firebase: κανόνες ασφαλείας              ~15 λεπτά   ← χωρίς αυτό δεν δουλεύει τίποτα
Γ. Δοκιμή στο κινητό σου                    ~15 λεπτά
Δ. Πολιτική απορρήτου σε δημόσιο URL        ~10 λεπτά
Ε. Λογαριασμός Play + η εφαρμογή            ~30 λεπτά + αναμονή ταυτοποίησης
ΣΤ. Το πρώτο .aab                            ~20 λεπτά   ← το δύσκολο
Ζ. 12 δοκιμαστές, 14 μέρες                  αναμονή
Η. Παραγωγή                                  ~10 λεπτά + 1-7 μέρες έλεγχος
```

# ΜΕΡΟΣ Α — GitHub

## Α1. Φτιάξε ένα token για τον εαυτό σου

Το κλειδί υπογραφής θα φτιαχτεί μέσα στο GitHub και θα αποθηκευτεί μόνο του.
Για να μπορεί να το αποθηκεύσει, χρειάζεται άδεια από σένα.

Άνοιξε: <https://github.com/settings/personal-access-tokens/new>

| Πεδίο | Τι βάζεις |
|---|---|
| Token name | `agios-nektarios-secrets` |
| Expiration | 90 days |
| Repository access | **Only select repositories** → `o-agios-nektarios-mou` |
| Permissions → Repository → **Secrets** | **Read and write** |

**Generate token** → σου δείχνει μια συμβολοσειρά `github_pat_...` **μία μόνο
φορά**. Αντίγραψέ τη τώρα.

Τώρα άνοιξε:
<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/settings/secrets/actions/new>

- Name: `ADMIN_TOKEN`
- Secret: επικόλλησε το token
- **Add secret**

✅ **Πέτυχε όταν:** στη λίστα των secrets βλέπεις `ADMIN_TOKEN`.

## Α2. Βάλε τη ρύθμιση του Firebase

Αυτό είναι το πρώτο από τα δύο αρχεία `.json` που θέλουν text editor.

1. <https://console.firebase.google.com> → το project σου → γρανάζι →
   **Project settings** → κάτω, στο *Your apps*, η εφαρμογή Android →
   **google-services.json** (κουμπί λήψης)
2. Ο Chrome το κατεβάζει. **Άνοιξέ το με τον text editor** (Λήψεις →
   παρατεταμένο πάτημα στο αρχείο → *Άνοιγμα με*)
3. Μενού του editor → **Select all** → **Copy**
4. <https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/settings/secrets/actions/new>
   - Name: `GOOGLE_SERVICES_JSON`
   - Secret: επικόλληση
   - **Add secret**

> Αν δεν έχεις ακόμα project στο Firebase, όλα τα βήματα είναι στο
> `docs/PHONE-SETUP.md` — και αυτά από κινητό.

✅ **Πέτυχε όταν:** υπάρχουν δύο secrets στη λίστα.

## Α3. Φτιάξε το κλειδί υπογραφής

Το κλειδί υπογραφής είναι το μόνο πράγμα σε όλη τη διαδικασία που **δεν
ξαναφτιάχνεται**. Αν χαθεί, το Play δεν δέχεται πια ενημερώσεις της
εφαρμογής σου· θέλει διαδικασία επαναφοράς με τη Google.

Γι' αυτό δεν περνάει από τα χέρια σου καθόλου: φτιάχνεται μέσα στον
υπολογιστή του GitHub και γράφεται κατευθείαν στα secrets. Δεν τυπώνεται
πουθενά — και δεν πρέπει, γιατί **αυτό το repository είναι δημόσιο** και τα
logs των Actions τα διαβάζει ο καθένας.

Άνοιξε:
<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/actions/workflows/bootstrap-key.yml>

**Run workflow** → στο πεδίο γράψε `ΝΑΙ` → **Run workflow**.

Περίμενε ~1 λεπτό, μπες στο run και δες τη **Summary**. Δείχνει δύο
αποτυπώματα, SHA1 και SHA256. Δεν είναι μυστικά — υπάρχουν μέσα σε κάθε
υπογεγραμμένο APK — και τα χρειάζεσαι αμέσως τώρα.

✅ **Πέτυχε όταν:** στα secrets υπάρχουν τώρα **έξι**: `ADMIN_TOKEN`,
`GOOGLE_SERVICES_JSON`, `UPLOAD_KEYSTORE_BASE64`, `UPLOAD_STORE_PASSWORD`,
`UPLOAD_KEY_PASSWORD`, `UPLOAD_KEY_ALIAS`.

> ⚠️ Μην ξανατρέξεις ποτέ αυτό το workflow μετά την πρώτη δημοσίευση στο Play.
> Φτιάχνει **καινούριο** κλειδί, και τότε το Play απορρίπτει κάθε επόμενο
> ανέβασμα. Γι' αυτό σου ζητάει να γράψεις `ΝΑΙ` με το χέρι.

## Α4. Τα αποτυπώματα στο Firebase

Χωρίς αυτό, το «Συνέχεια με Google» αποτυγχάνει σε κάθε συσκευή.

Firebase Console → **Project settings** → η εφαρμογή Android →
**Add fingerprint** → βάλε το SHA1 → ξανά **Add fingerprint** → βάλε το
SHA256.

Θα προσθέσεις άλλα δύο αργότερα (βήμα ΣΤ4), όταν θα υπάρχουν.

# ΜΕΡΟΣ Β — Οι κανόνες ασφαλείας

**Αυτό είναι το πιο σημαντικό βήμα του οδηγού.**

Οι κανόνες του Firestore δεν είναι κώδικας της εφαρμογής. Ζουν στον
διακομιστή της Google και ανεβαίνουν χωριστά. Μέχρι να ανέβουν:

- η ιδιωτικότητα των τηλεφώνων **δεν ισχύει** — είναι οι κανόνες που την
  επιβάλλουν, όχι η εφαρμογή
- συναγερμοί, ημερολόγιο, τηλέφωνα, συνομιλίες, ονόματα δρόμων και το σπίτι
  στον χάρτη βγάζουν «δεν επιτρέπεται»

**Δεν έχουν ανέβει ποτέ.**

## Β1. Το κλειδί του Firebase

Το δεύτερο αρχείο `.json` που θέλει text editor.

1. Firebase Console → γρανάζι → **Project settings** → καρτέλα
   **Service accounts** → **Generate new private key** → *Generate key*
2. Κατεβαίνει ένα `.json`. Άνοιξέ το με τον text editor, Select all, Copy.
3. <https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/settings/secrets/actions/new>
   - Name: `FIREBASE_SERVICE_ACCOUNT`
   - Secret: επικόλληση

> Αυτό το αρχείο δίνει πλήρη πρόσβαση στο project σου. Μην το στείλεις
> πουθενά αλλού, και σβήσ' το από τις Λήψεις όταν τελειώσεις.

## Β2. Ανέβασέ τους

<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/actions/workflows/deploy-rules.yml>

**Run workflow** → άφησε το *dry run* κενό → **Run workflow**.

Τρέχει πρώτα 241 tests στον εξομοιωτή και μόνο αν περάσουν όλα ανεβάζει.
Κανόνες που κόβουν κάτι που δεν έπρεπε είναι χειρότεροι από κανόνες που δεν
ανέβηκαν: σπάνε την εφαρμογή σε όλους ταυτόχρονα και δεν φαίνεται γιατί.

✅ **Πέτυχε όταν:** Firebase Console → **Firestore Database** → **Rules** και
η ημερομηνία πάνω είναι η σημερινή.

> **Αν σκάσει με «permission denied»:** ο λογαριασμός υπηρεσίας δεν έχει
> δικαίωμα. Google Cloud Console → **IAM** → βρες τον `firebase-adminsdk…` →
> μολύβι → *Add another role* → **Firebase Rules Admin** και
> **Cloud Datastore Index Admin** → Save. Ξανατρέξε το workflow.
>
> **Η εναλλακτική χωρίς κλειδί:** άνοιξε
> <https://raw.githubusercontent.com/grigoriosdimopoulos/o-agios-nektarios-mou/main/firebase/firestore.rules>,
> παρατεταμένο πάτημα → Επιλογή όλων → Αντιγραφή, και επικόλλησέ το στο
> Firebase Console → Firestore → Rules → **Publish**. Κάνει την ίδια δουλειά
> για τους κανόνες· χάνει μόνο τις ρυθμίσεις ευρετηρίων, που είναι θέμα
> κόστους και όχι λειτουργίας.

# ΜΕΡΟΣ Γ — Δοκίμασέ την στο κινητό σου

Τίποτα από αυτή την εφαρμογή δεν έχει τρέξει ποτέ σε αληθινή συσκευή. Όλα
έχουν επαληθευτεί με tests, με τον εξομοιωτή των κανόνων και με renders — ο
χάρτης ειδικά **δεν αποδίδεται καθόλου** εκτός συσκευής, οπότε είναι το πρώτο
πράγμα που πρέπει να δεις με τα μάτια σου.

Εδώ το κινητό είναι πλεονέκτημα, όχι εμπόδιο.

1. Άνοιξε
   <https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/releases>
2. Στην τελευταία έκδοση, πάτα το αρχείο `app-preview.apk`
3. Ο Chrome θα ρωτήσει αν είσαι σίγουρος → **Λήψη**
4. Πάτα το από τις Λήψεις → *Άγνωστη προέλευση* → **Εγκατάσταση**

Έλεγξε **έξι** πράγματα:

| | Τι να δεις |
|---|---|
| 1 | Σύνδεση με Google — δουλεύει |
| 2 | Ο χάρτης ανοίγει και δείχνει πινέζες |
| 3 | Πάνω αριστερά υπάρχει το **κόκκινο «Έκτακτο»** |
| 4 | Νέα αναφορά με φωτογραφία — ανεβαίνει |
| 5 | Ένας συναγερμός φτάνει σε δεύτερο κινητό |
| 6 | Έρχεται ειδοποίηση |

> Το στιγμιότυπο που έστειλες **δεν είχε** το κόκκινο «Έκτακτο». Αν λείπει και
> τώρα, είναι σφάλμα και θέλει διόρθωση **πριν** το ανέβασμα — είναι το κουμπί
> του συναγερμού, ο λόγος που υπάρχει η εφαρμογή.

Το σημείο 5 θέλει δεύτερο κινητό. Ζήτα από κάποιον να εγκαταστήσει το ίδιο
APK· θα το χρειαστείς ούτως ή άλλως στο μέρος Ζ.

# ΜΕΡΟΣ Δ — Πολιτική απορρήτου σε δημόσιο URL

Το Play θέλει **σύνδεσμο**, όχι αρχείο, και ο ελεγκτής τον ανοίγει.

## Δ1. Βάλε το email σου

Άνοιξε στον browser:
<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/edit/main/store/privacy-policy.el.md>

Πήγαινε στο τέλος. Αντικατέστησε το `ΣΥΜΠΛΗΡΩΣΕ ΕΔΩ: email επικοινωνίας` με
μια πραγματική διεύθυνση. **Commit changes**.

Κάνε το ίδιο για την αγγλική:
<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/edit/main/store/privacy-policy.en.md>
(εκεί γράφει `FILL IN: contact email address`).

> Αυτή η διεύθυνση γίνεται δημόσια. Αν δεν θέλεις το προσωπικό σου email,
> φτιάξε ένα καινούριο τώρα — θα το ζητήσει και το Play σε δικό του πεδίο.

Οι σελίδες ξαναφτιάχνονται μόνες τους με κάθε αλλαγή· δεν χρειάζεται να κάνεις
τίποτα άλλο.

## Δ2. Άναψε το GitHub Pages

<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/settings/pages>

- Source: **Deploy from a branch**
- Branch: **main**, φάκελος **/docs** → **Save**

Μετά από 1–2 λεπτά το URL είναι:

```
https://grigoriosdimopoulos.github.io/o-agios-nektarios-mou/privacy.html
```

✅ **Πέτυχε όταν:** ανοίγει σε **ανώνυμη καρτέλα** και **δεν** έχει κόκκινο
πλαίσιο στο τέλος. Το κόκκινο σημαίνει ότι το email δεν μπήκε.

## Δ3. Λογαριασμός για τον ελεγκτή

Η εφαρμογή θέλει σύνδεση. Χωρίς λογαριασμό, ο ελεγκτής βλέπει οθόνη σύνδεσης
και **απορρίπτει** — είναι από τους πιο συνηθισμένους λόγους απόρριψης.

Φτιάξε **καινούριο** λογαριασμό μέσα από την εφαρμογή — όχι δικό σου, όχι
διαχειριστή — και κράτα email και κωδικό. Θα τα δώσεις στο βήμα ΣΤ6.

# ΜΕΡΟΣ ΣΤ — Το πρώτο ανέβασμα

Το δύσκολο κομμάτι. Μία φορά.

## ΣΤ1. Φτιάξε την έκδοση

<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/releases/new>

- **Choose a tag** → γράψε `v1.0.0` → **Create new tag on publish**
- Title: `1.0.0`
- **Publish release**

Αυτό ξεκινάει το build. Δες το εδώ:
<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/actions>

Παίρνει ~10 λεπτά. Τρέχει τα unit tests, τα renders και τα 241 tests των
κανόνων πριν υπογράψει οτιδήποτε.

✅ **Πέτυχε όταν:** στη σελίδα του release εμφανίζονται δύο αρχεία,
`app-release.aab` και `app-preview.apk`.

## ΣΤ2. Κατέβασε το `.aab`

Στη σελίδα του release, πάτα το **`app-release.aab`**. Ο Chrome θα
προειδοποιήσει· **Λήψη**. Πάει στις Λήψεις.

> Μην πάρεις το αρχείο από την καρτέλα *Actions* — εκεί κατεβαίνει ως `.zip`
> και θα πρέπει να το αποσυμπιέσεις. Από τη σελίδα του **release** κατεβαίνει
> έτοιμο.

## ΣΤ3. Ανέβασέ το

Chrome → μενού (⋮) → ✅ **Desktop site**. Γύρνα το κινητό **οριζόντια**.
Θα είναι μικρό. Κάνε ζουμ με δύο δάχτυλα· δουλεύει.

Play Console → **Test and release** → **Testing** → **Closed testing** →
**Create new release**.

> ⚠️ **Closed**, όχι *Internal*. Μόνο η κλειστή δοκιμή μετράει για τις 14
> μέρες. Η εσωτερική εγκαθιστά μια χαρά και **δεν προχωράει τίποτα** — είναι
> ένας εύκολος τρόπος να χάσεις δύο βδομάδες.

- **Upload** → επιλογέας αρχείων → **Λήψεις** → `app-release.aab`
- Το Play θα προτείνει **Play App Signing** → **δέξου το**
- Release notes: δυο γραμμές, στα ελληνικά
- **Save** → **Review release** → **Start rollout to Closed testing**

✅ **Πέτυχε όταν:** βλέπεις `1.0.x (x)` και καμία κόκκινη προειδοποίηση.

## ΣΤ4. Τα άλλα δύο αποτυπώματα ⚠️

**Το βήμα που ξεχνιέται και σπάει τη σύνδεση σε κάθε εγκατεστημένο αντίγραφο.**

Με το Play App Signing, η Google υπογράφει η ίδια αυτό που φτάνει στα κινητά —
με **δικό της** κλειδί, διαφορετικό από το δικό σου. Το Firebase δεν το ξέρει
ακόμα.

Play Console → **Test and release** → **Setup** → **App signing**. Εκεί
υπάρχουν **δύο** πιστοποιητικά:

- *App signing key certificate* — της Google ← **αυτό λείπει**
- *Upload key certificate* — το δικό σου, το έβαλες ήδη στο Α4

Πάρε SHA-1 και SHA-256 από το **πρώτο** και βάλ' τα στο Firebase Console →
Project settings → η εφαρμογή Android → **Add fingerprint**.

✅ **Πέτυχε όταν:** το «Συνέχεια με Google» δουλεύει σε κινητό που κατέβασε την
εφαρμογή **από το Play**, όχι με sideload.

## ΣΤ5. Οι δοκιμαστές

**Closed testing** → **Testers** → **Create email list** → βάλε τα emails.

Πάρε το **Copy link** και στείλ' το μαζί με το μήνυμα του
`store/minyma-oikistes.md` και το PDF.

Κάθε άτομο πρέπει να: ανοίξει τον σύνδεσμο → *Become a tester* → εγκαταστήσει
από το Play → **και να την ανοίξει**. Από το 2026 το Play κοιτάει αν οι
δοκιμαστές την **χρησιμοποίησαν** πραγματικά, όχι μόνο αν την κατέβασαν.

## ΣΤ6. Η καταχώριση

Όσο τρέχουν οι 14 μέρες, γέμισε τα υπόλοιπα. Όλα από το κινητό, σε
Desktop site.

**Grow → Store presence → Main store listing**

| Πεδίο | Τι βάζεις |
|---|---|
| App name | `Άγιος Νεκτάριος` |
| Short description | `Ο χάρτης, τα προβλήματα και τα νέα του χωριού μας.` |
| Full description | από `store/PLAY-STORE.md` §5.3 |
| App icon | `store/app-icon-512.png` |
| Feature graphic | `store/feature-graphic.png` |
| Phone screenshots | `store/screenshots/` — **`hartis-play.png` πρώτο** |

Τις εικόνες κατέβασέ τις στο κινητό από τη σελίδα του καθενός στο GitHub
(κουμπί *Download raw file*).

**Store settings:** κατηγορία *Κοινωνικά*· email το δικό σου· τηλέφωνο και
website κενά.

**Policy → App content** — οι απαντήσεις είναι στο `store/PLAY-STORE.md` §8,
συμπληρωμένες από τον κώδικα:

1. **Privacy policy** → το URL από το Δ2
2. **App access** → *Some functionality restricted* + ο λογαριασμός από το Δ3
3. **Ads** → Όχι
4. **Content rating** → ερωτηματολόγιο, κατηγορία *Social*
5. **Target audience** → **18+**
6. **Data safety** → ο πίνακας του §8.6 — *Shared* = **Όχι** παντού
7. **Government / Financial / Health** → Όχι σε όλα

✅ **Πέτυχε όταν:** κάθε γραμμή στο *App content* έχει πράσινο ✓.

# ΜΕΡΟΣ Ζ — 12 δοκιμαστές, 14 μέρες

Ο κανόνας ισχύει για κάθε προσωπικό λογαριασμό που άνοιξε μετά τις
13 Νοεμβρίου 2023. Δηλαδή για τον δικό σου.

- **12 διαφορετικοί λογαριασμοί Google**, μέσα από τον σύνδεσμο του ΣΤ5
- **14 συνεχόμενες μέρες**
- Αν πέσεις κάτω από 12, **ο μετρητής μηδενίζει** — δεν παγώνει, μηδενίζει

Βάλε **15**, όχι 12. Κάποιος θα αλλάξει κινητό, κάποιος θα την απεγκαταστήσει.
Σε ένα χωριό 200 σπιτιών, 15 άτομα βρίσκονται.

Παράλληλα, οι δοκιμαστές είναι το μόνο σου feedback πριν βγει στον κόσμο.

# Μετά: κάθε ενημέρωση

Από εδώ και πέρα μια νέα έκδοση είναι **δύο πατήματα**: φτιάχνεις ένα tag στο
<https://github.com/grigoriosdimopoulos/o-agios-nektarios-mou/releases/new>
και κατεβάζεις το `.aab` για το Play.

Αν θέλεις να φεύγει και **μόνο του** στο Play, χρειάζεται ένα ακόμα κλειδί:
Play Console → **Setup** → **API access** → φτιάξε λογαριασμό υπηρεσίας, δώσ'
του δικαίωμα *Release manager*, κατέβασε το JSON και βάλ' το ως secret
`PLAY_SERVICE_ACCOUNT_JSON`. Μετά:
*Actions* → **Release** → **Run workflow** → ✅ *publish to play*.

Αυτό **δεν** δουλεύει για το πρώτο ανέβασμα — το Play αρνείται το API μέχρι να
υπάρξει η εφαρμογή στο Console, που γίνεται μόνο με ανέβασμα από άνθρωπο. Γι'
αυτό το μέρος ΣΤ γίνεται μία φορά με το χέρι.

## Μια ημερομηνία που θα ξαναρθεί

Από **31 Αυγούστου 2026** το Play δεν δέχεται νέα εφαρμογή — ούτε ενημέρωση —
που δεν στοχεύει Android 16 (API 36). Η εφαρμογή στοχεύει ήδη 36· δεν έχεις να
κάνεις τίποτα.

Το γράφω γιατί **ξανασυμβαίνει κάθε χρόνο**, περίπου τον ίδιο μήνα. Αν κάποια
στιγμή το Play απορρίψει ένα `.aab` λέγοντας κάτι για *target API level*, αυτό
είναι, και αλλάζει με μία γραμμή στο `app/build.gradle.kts`.

# Τι πάει στραβά συνήθως

| Σύμπτωμα | Αιτία |
|---|---|
| «Συνέχεια με Google» αποτυγχάνει μόνο από το Play | Λείπουν τα αποτυπώματα του **app signing key** (ΣΤ4) |
| Απόρριψη: «could not access the app» | Δεν δόθηκε λογαριασμός δοκιμής (Δ3) |
| «Δεν επιτρέπεται» παντού μέσα στην εφαρμογή | Δεν ανέβηκαν οι κανόνες (Β2) |
| Πέρασαν 14 μέρες και δεν άνοιξε τίποτα | Ήταν *Internal* αντί για *Closed* (ΣΤ3) |
| Το Play αρνείται το `.aab` ως παλιό | `versionCode` — το Action το ανεβάζει μόνο του σε κάθε commit |
| Το bootstrap workflow σκάει αμέσως | Λείπει το `ADMIN_TOKEN` (Α1) ή δεν έγραψες `ΝΑΙ` |
| Data safety «incomplete» | Ξέχασες *Data deletion* — ναι, γίνεται μέσα από την εφαρμογή |
| Η σελίδα απορρήτου έχει κόκκινο πλαίσιο | Δεν μπήκε το email (Δ1) |
